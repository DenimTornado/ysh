# Домашний пульт · версия 2

React + TypeScript + Vite. Список устройств строится из `user-info`, без UUID в исходниках.

## Запуск и проверка

Node.js 22.6+.

```sh
npm install
cp .env.example .env
npm run dev
```

В `.env` укажите `VITE_API_URL` серверного прокси и `VITE_YANDEX_CLIENT_ID` OAuth-приложения. Адрес приложения должен быть разрешён в настройках OAuth; права — `iot:view iot:control`.

```sh
npm run build
npm run lint
npm test
```

## Три блока

- **Устройства.** Общие компоненты для `on_off`, `range`, `mode`, `toggle`, `color_setting`. Все переданные функции этих типов отображаются, включая дополнительные режимы, медиакнопки, канал и громкость. Набор контролов определяется возможностями, а не типом или именем устройства. Медиапульты свёрнуты по умолчанию. Неизвестные служебные capabilities доступны для просмотра отдельно; команды без известного контракта не отправляются.
- **Сценарии.** Все сценарии, статус активности и запуск активных. Публичный API Яндекса документирует [запуск](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-scenario), но не изменение активности. Включение и отключение выполняется в «Доме с Алисой»; здесь нет имитирующего это локального переключателя.
- **Датчики.** Отдельная вкладка со всеми `properties` всех устройств: вода, температура, влажность, батарея, электричество, события и новые неизвестные свойства. Для каждого датчика сохраняются видимость и порядок. Неизвестное значение показано как «Нет данных», нулевое сохраняется. Видимые показания можно скопировать.

В настройках устройств доступны видимость, порядок, абсолютный числовой вес и группы питания. Чем меньше вес, тем выше устройство; стрелки автоматически назначают веса с шагом 10. Такие же веса доступны для датчиков. Скрытие устройства не скрывает его измерения. По умолчанию показываются все устройства из ответа Яндекса, включая розетки, телевизоры, сезонные и устройства без публичных команд. Устройство без команд остаётся в списке с пояснением, а его свойства также доступны в показаниях. Счётчик в шапке показывает исходное число устройств; число карточек может быть меньше, когда несколько каналов объединены в одну группу.

Каналы одного физического Zigbee-выключателя с совпадающими домом, комнатой и базовым `external_id` объединяются автоматически, если из публичных команд у них только питание. Группу можно разъединить или создать вручную. Наличие дополнительных режимов и диапазонов не теряется: для ручных групп они доступны в «Дополнительном управлении» каждого участника. При отсутствии участника общие кнопки блокируются.

Настройки текущей версии хранятся в `yandex_smart_home_v3` в браузере. При переходе с версии 2 сохраняются порядок, группы и настройка датчиков, а видимость устройств сбрасывается, чтобы новая версия один раз показала полный список из ответа Яндекса. После этого скрытие устройств снова сохраняется. Настройки датчиков начинаются с отображения всех полученных свойств.

## Пресеты

`src/components/color-controls.tsx` — общий виджет цвета для любых совместимых устройств. Пользователь создаёт пресеты «Быстрого света» из температуры и яркости, а также собственный список именованных цветов. Настройки сохраняются отдельно для каждого устройства в браузере; числовые значения проверяются по актуальным диапазонам при применении.

## Серверный контракт и ограничения

Сервер находится вне репозитория. Клиент отправляет POST на `VITE_API_URL`:

- `{ token, endpoint: "user-info" }` → `devices`, `rooms`, `scenarios`.
- `{ token, endpoint: "device-action", payload: { devices: [{ id, actions: [{ type, state }] }] } }`.
- `{ token, endpoint: "run-scenario", payload: { scenario_id } }`.

Прокси должен передавать `state.relative`, пакеты действий и ошибки устройств без изменений. Клиент проверяет HTTP-статус, JSON, `error_code` и вложенные `action_result`, включая частичные отказы. Команды не повторяются автоматически. После отправки запрашивается состояние; успешные команды дополнительно сверяются через 1,5 секунды. Данные также обновляются кнопкой, при возврате на вкладку и каждые две минуты на видимой вкладке.

ИК-устройства не подтверждают доставку сигнала. Громкость с `random_access: false` меняется относительными шагами, без выдуманного текущего уровня. `null` и нулевой timestamp не означают выключенное или недоступное устройство.

Для Wi‑Fi, эквалайзера, внутренних `audio_player`, обученных ИК-кнопок и других закрытых capabilities нужен подтверждённый серверный адаптер. Само наличие поля в ответе не гарантирует управление через публичный API. Эти данные не скрываются, но неизвестные операции не подменяются похожими публичными командами.

Тесты используют подменённый API и не управляют реальным домом.
